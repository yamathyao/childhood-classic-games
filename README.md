## 横刀立马

棋盘为 **4 列 × 5 行**，共 10 枚棋子、18 个占用格和 2 个空格：

| 棋子 | 数量 | 尺寸（宽 × 高） |
| --- | --- | --- |
| 曹操 | 1 | 2 × 2 |
| 关羽 | 1 | 2 × 1 |
| 张飞、马超、赵云、黄忠 | 各 1 | 1 × 2 |
| 兵 | 4 | 1 × 1 |

关羽与四名竖向武将合计“五将”。初始布局按用户提供的图稿逐格核对如下（重复名字表示同一枚棋子）：

| 第 1 列 | 第 2 列 | 第 3 列 | 第 4 列 |
| --- | --- | --- | --- |
| 张飞 | 曹操 | 曹操 | 马超 |
| 张飞 | 曹操 | 曹操 | 马超 |
| 赵云 | 关羽 | 关羽 | 黄忠 |
| 赵云 | 兵 | 兵 | 黄忠 |
| 兵 | 空 | 空 | 兵 |

棋子只能上下左右平移，不可旋转、重叠或穿过其他棋子。曹操左上角到达零起点坐标 `(1, 3)`，即占据底部中央 2×2 区域，判为通关。

一次松手提交的有效直线滑动计 1 步，无论移动一格或多格；转弯需重新拖动，另计一步。无效移动不计步，悔棋撤销上一步并扣回步数。第一次有效移动时开始计时，计时显示在步数旁；返回合集、切到后台和重新打开会保留已用时间，通关后停止计时。本项目不将不同计步口径的“81 步”作为达标标准。

合集首页的华容道卡片内提供精致的“选择对局”按钮，选定后再进入棋局；棋局页不再切换布局，左上角“游戏合集”和底部“退出棋局”都可以返回合集。当前收录参考截图中的 32 局：每局保存自己的棋块尺寸、空位和曹操起点，不能把其他局面当成横刀立马的中局截图。截图中的参考步数保存在 `referenceMoves` 字段并显示在选择器中；游戏内步数仍按一次松手的有效直线滑动计数。每个布局的进度、计时和最佳成绩分别保存在 `klotski.<levelId>.v1` 与 `klotski.<levelId>.best.v1`，最近选择项保存在 `klotski.currentLevel`。

### 32 局参考布局

32 局来自用户提供的参考图，棋盘按 4 列 × 5 行逐格转录。曹操始终为 2 × 2，两个黑色格为出口空位；关羽、张飞、马超、赵云、黄忠始终是同五枚武将棋子，横向或竖向只表示当前布局中的方向。其余棋块按图中的边界记录。局名与参考步数只作为资料标签，不改变当前游戏的计步规则。选择器使用分页显示，每页 8 局，避免小屏触控区域过小。

## 钻地挑战

以初代街机《Mr. Driller》为玩法参照，使用自行绘制的角色、矿块和补给素材。入口改为 **500 米标准挑战**与 **1000 米深井挑战**，矿井有 10 列可操作空间；原先 10 个石墙分段短关已被替换。

左右移动并钻开相邻方块，下键向下钻，上键只钻头顶方块；支持四向滑动与长按方向连续操作。钻开彩色块时，相连同色块一起消除。悬空块显示 `!`，短暂预警后自行坠落；落地的同色组达到 4 格时自动消除，进一步触发落块和连锁。棕色 `×` 硬块需要钻 5 次，击破扣除 20 点氧气；利用落块连成 4 格消除硬块不会支付这笔氧气。

首次有效操作启动实时模拟，**静止也会耗氧、落块也会继续运动**；暂停、返回合集和切后台会停止模拟。`O₂` 恢复 20 点氧气，上限 100。每次挑战提供 3 次生命，受撞击或耗尽氧气后可消耗生命继续；继续时在当前位置清出避让空间并提供短暂保护。到达目标深度立即通关；500 米通关后可进入 1000 米挑战。

每次新挑战用新种子生成连续矿层，越深硬块越多；继续存档保留地图、硬块伤害、悬空计时、氧气、生命和位置。实时模拟以固定时间步运行，动画不修改逻辑状态；恢复时先暂停，避免加载期间被砸或耗氧。新进度键为 `driller.arcade-500.v2` / `driller.arcade-1000.v2`，最佳成绩键在关卡 ID 后使用 `.best.v2`。旧版短关存档不删除、不混用。

**复现范围：** 当前没有取得可核验的初代原始地图、生成器或逐帧参数，本实现不是原版关卡数据的直接移植。公开资料入口在本次开发环境中超时或返回拒绝访问；矿层生成、补给间距、每米对应一行、耗氧速度、落块延迟、计分和续命保护均为本项目实现，需要后续结合初代实机录像继续校准。500 米当前每秒耗氧 1 点、预警 500 毫秒、每 8 行布置补给；1000 米每 850 毫秒耗氧 1 点、预警 400 毫秒、每 10 行布置补给。两档落块每 100 毫秒前进一格。

`npm run driller:verify` 用每次行动间隔 150 毫秒的自动操作验证两档默认种子的完整通关，包含避开硬块、寻找补给和实时落块。该检查证明受测地图可玩，不代表所有随机种子的难度均已实机验收。

## 文字对战

根据用户提供的 HTML 原型改写为原生 Canvas 单人自动战斗。战前可以改名、重掷自身属性、选择长剑／大刀／长枪／短双刃／大斧／戟和强攻／守御／游斗姿态；点击「玩法」查看规则。长剑均衡迅捷，大刀伤害高且擅长暴击，长枪忽略 20% 防御，短双刃出招快且增加闪避，大斧忽略 55% 防御，戟攻击较长枪高、速度略慢并忽略 35% 防御。暴击伤害为普通攻击的 1.8 倍。六种武器分两行三列展示；长枪与戟使用明显长于身体的长杆，戟额外带月牙侧刃。旧存档中的大锤迁移为大斧，保留生命、连胜、属性与出招进度。

改名旁的骰子图标同时随机姓名和男女外观，包含常见姓氏、复姓与诗意江湖名字；避开最近 8 个姓氏、16 个名字和 64 个完整姓名，近期记录保存在本机。姓名和男女随机使用独立随机状态，立即保存，且不会改变战斗随机状态或双方属性。人物战斗区域显示角色姓名，旁边保留男女切换按钮；武器与姿态分组之间留出标题空间，下方战报框延伸到主按钮上方，使用 14px 字体与 24px 行距，按屏幕高度计算可见条数。姿态下方的说明随强攻／守御／游斗切换。每一战的准备阶段隐藏敌方六项数值，主画面与玩法弹窗都以问号显示；点击「开始交战」后揭示，暂停和恢复中途战斗继续显示，进入下一战时再次隐藏。

角色与武器采用简洁的 2D 线条风格，由本地配置的图像接口以 `gpt-image-2.5-sunburst` 生成、编辑，经过抠图、握持点对齐与离线拼装，输出 `assets/textbattle/fighters-2d.png` 的蓝男／蓝女／红男／红女四组、每组六种武器的透明图集。女性以马尾区分；点击战前我方上方的男女按钮切换外观，不影响属性或战斗随机状态，敌人外观随生成确定，双方外观保存在存档中。生成与编辑提示词保存在 `art-source/textbattle-sprites-2d*.prompt.txt`；处理工具 `tools/prepare-textbattle-art-2d.py` 需 Pillow 与本地原图 `tmp/textbattle-art-2d/isolated.png` 才能重新导出。合集封面、详情页与交战画面共用素材；每个场景仅加载一张图集（解码约 6 MiB），加载完重绘一次，退出释放引用与回调。图片加载或绘制失败时沿用 Canvas 武器和人物绘制。

第二版从战前决策入手：敌方随机持有六种武器之一，名号从 64 个武侠角色的谐音或近音名字中抽取：金庸 32 个、古龙 24 个、梁羽生和温瑞安各 4 个，如令狐充、西门吹鳕、楚流香、张丹峰。角色外观按名字原型的性别生成，避免连续两战重名；原名、作者和作品对应记录在 `games/textbattle/enemy-names.js` 中，游戏只显示谐音名。名号不影响属性，没有职业加成或职业特性。技能绑定武器，无需手动选择；点击「武器技」或「玩法」查看基础玩法、武器技能和克制图谱。敌方六项数值仍在开战后揭示。

武器克制形成一个六武器环，每种武器克制一种、被一种克制，其余关系势均力敌：

| 我方武器 | 克制对象 | 设计依据 |
| --- | --- | --- |
| 长剑 | 短双刃 | 剑锋距离压制短刃 |
| 短双刃 | 大斧 | 灵巧快刃绕开重斧 |
| 大斧 | 戟 | 重斧破开戟的架势 |
| 戟 | 长枪 | 戟钩牵制枪杆 |
| 长枪 | 大刀 | 长杆压制刀的近身 |
| 大刀 | 长剑 | 势大劈斩压制剑锋 |

图谱为 6×6 武器矩阵：金色「→」表示专属克制，我方伤害 +18%；红色「←」表示被克制，敌方伤害 +18%；蓝灰色「=」表示势均力敌，双方没有克制加成。同种武器势均力敌，矩阵框选当前对局。双方采用相同的武器技能与「武势」规则：武势满 100 后，下次出招自动释放技能，清空后重新积攒；没有额外的职业减伤、爆发或特殊闪避修正。

| 武势来源 | 积攒规则 |
| --- | --- |
| 造成伤害 | 每实际扣除对方 1% 生命上限，积攒 1.6 点 |
| 承受伤害 | 每实际损失自身 1% 生命上限，积攒 1.1 点 |
| 造成暴击 | 在伤害积攒之外，额外 +6 点 |
| 成功闪避 | 闪避者 +8 点，未命中者不获得伤害武势 |

双方属性面板显示武势条与数值，满值显示「待发」。伤害按实际扣血计算，减伤会减少双方伤害积攒，溢出伤害不计入；技能伤害也能积攒，技能未命中仍消耗满值，最多储存一次技能。内部以 0.01 点整数精度保存。每战武势归零，暂停和恢复存档保持原值。玩法指南的「武势机制」页说明计算方式。

每场胜利后，结果弹窗左右展示双方的实际总伤害、暴击次数、成功闪避次数、技能释放次数与武器克制关系。统计独立累积，不受战报仅保留最近 80 条的限制；技能未命中也算一次释放，闪避计在防守方。旧存档只能恢复保留战报的统计时，会明确标注。

点击「下一战」进入三选一强化，选完才进入下一战准备。候选从六种强化中抽取，排除已达上限的选项，显示当前数值与强化后的数值；候选不随退出或重载刷新，也不消耗战斗随机数。武器整轮锁定，选完强化后可调整姿态；双方每战满血，重新开始或「换人再战」清空本轮成长，历史纪录保留。第 100 战胜利后结束挑战，不再发放下一战强化。

| 强化 | 效果 | 选择上限 |
| --- | --- | --- |
| 淬锋 | 攻击 +1 | 99 次 |
| 养元 | 生命上限 +12 | 99 次 |
| 固守 | 防御 +2 | 99 次 |
| 疾行 | 原始有效攻速 +4%，累加 | 12 次，攻速最多 4/s |
| 破绽 | 暴击 +4 个百分点 | 8 次，最多 60% |
| 轻身 | 闪避 +3 个百分点 | 8 次，最多 45% |

敌方生命与攻击随战次平滑加速增长，防御缓慢线性增长；每五战为强敌，额外提升 6% 生命与 4% 攻击，下一战回到正常曲线。名号不带职业属性。旧存档的当前战斗保持原属性、规则和随机进度；胜利进入下一战时启用成长与新曲线，此前已完成的胜战按生命、攻击、防御轮流补齐强化。

`node tools/verify-textbattle-growth.cjs` 比较攻击、生存、速度三种强化优先级，在第 1／5／10／20／30／60／100 战与六种敌方武器对战，默认模拟 22,680 场，检查战斗时长与存档可恢复性。这是已获得对应战次奖励后的独立对局比较，不代表一路不败的通关率。

战斗反馈包含出招前倾、受击后仰、闪避侧移，以及命中／暴击／格挡飘字。保留六种武器的人物动作，移除攻击轨迹、受击线条和护身弧；护身未消耗时在属性面板显示「护身」。伤害数字显示在受击方外侧，暴击／格挡用小字标注，闪避独立显示；技能发动提示放在施放方顶部。同侧新飘字替换旧飘字，数字短暂放大、轻微上浮后淡出。武势条用 220 毫秒平滑增长，满值短暂描边提示后静态显示「待发」，释放时清空并重新积攒。最后一击展示约 400 毫秒后打开结果弹窗，胜负和连胜立即保存。动画数据不进入存档、不参与伤害计算，也不消耗战斗随机数；最多保留 6 个近期事件。沿用单个调度器，动画约 30 帧，出招之间只重绘战斗区域与武势条；特效结束后等待下次出招，暂停、后台和退出立即停止绘制。

`node tools/verify-textbattle.cjs` 使用相同基础属性模拟 10,800 场对战（6×6 武器组合、我方 3 种姿态、敌方强攻、100 个种子），并检查第 10／30／60／100 战的存档与武势边界。当前首战我方平均首次释放约 3.76–4.11 秒，各武器平均 1.72–1.87 次技能；这是一组均衡基础属性的模拟结果，实战会随随机属性、克制及战次变化。

| 武器 | 技能 | 本次效果 |
| --- | --- | --- |
| 长剑 | 点锋 | 必中，伤害 +15% |
| 大刀 | 重斩 | 伤害 +45% |
| 长枪 | 贯甲 | 无视防御，闪避判定减半 |
| 短双刃 | 双袭 | 两刃合击，伤害 +35%，合并为一次伤害结算 |
| 大斧 | 裂甲 | 无视防御，伤害 +20% |
| 戟 | 架势 | 伤害 +20%，下一次命中的敌方攻击减伤 25% |

护身不叠加，对方未命中时不消耗护身；没有新增技能选择、主动操作或持续计时器。

开战后自动按速度出招，武器与姿态在交战期间锁定。同一时刻双方出招随机决定先后，致命一击后立即停止战斗。武器仅在第一战准备阶段可选择，本轮挑战后续战斗保持固定；「下一战」恢复满血并生成逐渐增强的敌人，仅可调整姿态。主界面顶部「重新开始」暂停战斗并请求确认：确认后从第一战开始，重新生成角色、属性与对手，清空当前连胜和战报，保留历史连胜纪录，并恢复武器选择；取消保留当前进度，中途交战需主动继续。每次挑战最多 100 战；重掷属性仍仅在第一战准备阶段开放。

交战画面下方用左右两个等尺寸面板展示我方（蓝色）和敌方（暖红色），各自集中展示武器、生命、攻击、防御、攻速（每秒出招）、暴击和闪避，随装备、姿态与生命变化更新；玩法、暂停和结果弹窗沿用相同的双方分栏。最近 80 次出招直接在主画面的战报框中滑动查看，武器技能显示名称，「克」表示克制增伤，「挡」表示减伤；旧战斗中的回血仍显示实际恢复量。战后弹窗的「查看战报」关闭弹窗并回到主画面，底部「查看战斗结果」可再次打开结果并进入下一战或重开。交战中滑动旧记录自动暂停，底部按钮在「暂停交战／继续交战」之间切换，继续后回到最新记录。切后台、退出或调整窗口大小会暂停；恢复进度后需主动继续，不会补算离线战斗。准备页与暂停页没有持续定时器，交战只使用一个调度器，攻击动画以约 30 帧绘制。

存档键为 `textbattle.v5`，战斗规则版本 5 保存双方武势、生命、出招冷却、随机状态与战报；无有效当前存档时依次尝试 `textbattle.v4`、`textbattle.v3`、`textbattle.v2` 和 `textbattle.v1`。旧存档保留：准备中的战局直接启用武势机制并取消职业属性，已开战的旧战局保留原战斗规则与出招进度，显示名号改为武侠谐音名；此前保存的魔头名称在加载时更换，保持原外观性别、属性和战斗随机状态。旧的每三次出招机制在当前战斗结束前保持，胜利进入下一战或重开后启用武势，避免中途改变战况。每次胜利立即更新 `textbattle.records.v1` 的本机连胜记录，同一挑战只保留一条最高成绩。当前为单人本机挑战。

## 打开项目

1. 在微信开发者工具中导入仓库根目录，项目类型为**小游戏**。
2. 使用已配置的小程序 AppID；自行部署时应使用具有小游戏资质的 AppID。
3. 入口是根目录 `game.js`，运行配置为 `game.json`，无需构建或安装运行时依赖。
4. 首页只展示游戏卡片，不放置进入、选关等操作按钮。点击卡片进入对应游戏的全屏详情页，详情页展示封面、玩法说明、当前进度，并提供“选择对局/选择关卡”和“进入游戏”。详情页左上角返回合集；推箱子遵循经典规则，全部木箱进入任意红色目标点即可通关。

存档与最佳成绩保存在本机，不会云同步。清除微信数据会移除记录；保存失败会在画面提示，当前会话仍可游玩。

## 验证

使用 Node.js 20 或更新版本，无需安装依赖：

```sh
npm test
npm run check
npm run sokoban:verify
```

测试覆盖精确布局、长距离移动防穿透、计步与悔棋、存档回放、场景监听、误触重置、中断手势、多指干扰、100 次连续移动和完整解局。动画帧测试额外检查触摸事件合帧、快速松手落点、吸附期间接续操作及完整通关。测试用搜索器按等尺寸棋子合并状态，找出通关路径后，通过实际规则及触摸控制器重放；搜索器不包含在发布包中。

资源回归可单独运行 `node --test --test-isolation=none tests/runtime-resources.test.js`：检查四个游戏的静止重绘次数、后台停止、退出清理，以及纹理缓存的容量和释放。华容道仅局部刷新计时，推箱子静止时不绘制，俄罗斯方块按棋盘变化绘制；钻地挑战在动画或可见状态变化时绘制，并缓存矿块纹理。高清像素密度保持原设置，实际 CPU、GPU、内存和耗电仍需在微信真机性能面板测量。

视觉验收使用 `npm run visual:qa`，需要本机安装 Playwright 与浏览器。可通过 `PLAYWRIGHT_MODULE` 指向已有 Playwright 模块，通过 `CHROME_EXECUTABLE` 指定浏览器。该工具使用实际小游戏模块与浏览器微信适配层，输出 320×568、375×667、390×844 三种尺寸的截图与本地预览到 `tmp/qa/`，检查真实 Canvas 绘制、动画和进度恢复。

**验证边界：**浏览器适配层与 Node 测试不能替代微信基础库、开发者工具上传包及真机触摸验收。

## 美术

当前主方案由 Canvas 本地绘制，无需网络：棋子使用固定随棋的不规则木纹、旧漆、倒角、凹槽与渐变细金线，保留古朴刻字。曹操与卒保留原配色；关羽用青玉、张飞用靛蓝、马超用古金、赵云用青灰、黄忠用紫檀色。六位角色的插画提示词见 [art-source/portraits.prompt.txt](art-source/portraits.prompt.txt)。API 已生成评审图集，作为备用方案暂未接入运行时。

推箱子改为经典“仓库番”主题：木墙、木地板、木箱、红色目标点和仓库工人。26 关基础教学参考 `shunyue1320/sokoban` 的 `mapdata100.js`，另精选 XSokoban 原版第 31–50 关作为 20 关挑战；选关页按基础关卡与挑战关卡分组，错误推法会触发死局提示，均可通过悔棋恢复。全部由 Canvas 2D 绘制，不增加图片包体积。

推箱子详情页参考维基百科[“倉庫番”](https://zh.wikipedia.org/wiki/%E5%80%89%E5%BA%AB%E7%95%AA)中经典仓库推箱子的木箱、目标标记与空间推理表达，素材均由 Canvas 2D 重新绘制，未直接打包来源截图；完整说明见 [docs/sokoban-materials.md](docs/sokoban-materials.md)。关卡文本来自 XSokoban 开源数据，项目保留原始来源和许可证说明。

俄罗斯方块详情页采用复古街机方向：进入游戏后使用深靛蓝棋盘、黄铜边框和七种高对比宝石色方块；首页与详情页仍沿用合集纸张背景。规则为经典 10×20 棋盘、七袋随机、旋转墙边修正、软降、硬降和逐级加速，所有素材均由 Canvas 2D 本地绘制。

棋子大字采用 [Ma Shan Zheng（马善政毛笔字）](https://github.com/googlefonts/mashanzheng)，按 SIL OFL 1.1 使用，许可随包保存在 `assets/lettering/OFL.txt`。仅提取“曹关张马赵黄卒”七个字的矢量轮廓（约 50 KB），通过 Canvas 路径绘制，避免设备系统字体差异与网络字体加载。小字保持原有风格。原始字体来自 Google Fonts，保存在不参与打包的 `art-source/lettering/`；Windows 下可运行 `./tools/build-piece-lettering.ps1` 重新生成轮廓。

- [按棋子比例放入棋盘的预览](art-source/portraits-piece-preview-v1.png)
