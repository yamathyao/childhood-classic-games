## 横刀立马

棋盘为 **4 列 × 5 行**，共 10 枚棋子、18 个占用格和 2 个空格：

| 棋子 | 数量 | 尺寸（宽 × 高） |
| --- | --- | --- |
| 曹操 | 1 | 2 × 2 |
| 关羽 | 1 | 2 × 1 |
| 张飞、马超、赵云、黄忠 | 各 1 | 1 × 2 |
| 兵 | 4 | 1 × 1 |

关羽与四名竖向武将合计“五将”。初始布局按用户提供的图稿逐格核对如下（重复名字表示同一枚棋子）：

| 第 1 列 | 第 2 列 | 第 3 列 | 第 4 列 |
| --- | --- | --- | --- |
| 张飞 | 曹操 | 曹操 | 马超 |
| 张飞 | 曹操 | 曹操 | 马超 |
| 赵云 | 关羽 | 关羽 | 黄忠 |
| 赵云 | 兵 | 兵 | 黄忠 |
| 兵 | 空 | 空 | 兵 |

棋子只能上下左右平移，不可旋转、重叠或穿过其他棋子。曹操左上角到达零起点坐标 `(1, 3)`，即占据底部中央 2×2 区域，判为通关。

一次松手提交的有效直线滑动计 1 步，无论移动一格或多格；转弯需重新拖动，另计一步。无效移动不计步，悔棋撤销上一步并扣回步数。第一次有效移动时开始计时，计时显示在步数旁；返回合集、切到后台和重新打开会保留已用时间，通关后停止计时。本项目不将不同计步口径的“81 步”作为达标标准。

合集首页的华容道卡片内提供精致的“选择对局”按钮，选定后再进入棋局；棋局页不再切换布局，左上角“游戏合集”和底部“退出棋局”都可以返回合集。当前收录参考截图中的 32 局：每局保存自己的棋块尺寸、空位和曹操起点，不能把其他局面当成横刀立马的中局截图。截图中的参考步数保存在 `referenceMoves` 字段并显示在选择器中；游戏内步数仍按一次松手的有效直线滑动计数。每个布局的进度、计时和最佳成绩分别保存在 `klotski.<levelId>.v1` 与 `klotski.<levelId>.best.v1`，最近选择项保存在 `klotski.currentLevel`。

### 32 局参考布局

32 局来自用户提供的参考图，棋盘按 4 列 × 5 行逐格转录。曹操始终为 2 × 2，两个黑色格为出口空位；关羽、张飞、马超、赵云、黄忠始终是同五枚武将棋子，横向或竖向只表示当前布局中的方向。其余棋块按图中的边界记录。局名与参考步数只作为资料标签，不改变当前游戏的计步规则。选择器使用分页显示，每页 8 局，避免小屏触控区域过小。

## 打开项目

1. 在微信开发者工具中导入仓库根目录，项目类型为**小游戏**。
2. 使用已配置的小程序 AppID；自行部署时应使用具有小游戏资质的 AppID。
3. 入口是根目录 `game.js`，运行配置为 `game.json`，无需构建或安装运行时依赖。
4. 首页进入华容道。返回合集后可继续解局；重开必须经过确认。

存档与最佳成绩保存在本机，不会云同步。清除微信数据会移除记录；保存失败会在画面提示，当前会话仍可游玩。

## 项目结构

```text
game.js                   # 单一 Canvas、场景切换、前后台与尺寸事件
game.json                 # 竖屏小游戏配置
project.config.json       # 开发者工具与打包配置
common/
  canvas.js               # 通用绘制、材质与按钮
  screen.js               # 安全区、窗口尺寸与像素比
games/
  index/game.js           # 合集首页
  klotski/
    levels.js             # 关卡与棋子定义
    rules.js              # 纯规则、计步、悔棋与存档重放校验
    layout.js             # 绘制与命中检测共用的布局
    game.js               # 触摸控制、吸附、游戏状态与生命周期
    renderer.js           # 棋盘、棋子与弹层绘制
    art.js                # 武将素材加载入口
art-source/               # 美术源文件与生成提示词，不参与打包
tests/                    # 规则与触摸回归测试，不参与打包
tools/                    # 项目检查与浏览器视觉验收
```

每个场景返回 `dispose / resize / hide / show` 接口。总入口负责调用；退出时必须解除该场景全部监听，避免旧首页事件重新初始化游戏。所有动作使用与绘制共用的控件范围。

## 验证

使用 Node.js 20 或更新版本，无需安装依赖：

```sh
npm test
npm run check
```

测试覆盖精确布局、长距离移动防穿透、计步与悔棋、存档回放、场景监听、误触重置、中断手势、多指干扰、100 次连续移动和完整解局。动画帧测试额外检查触摸事件合帧、快速松手落点、吸附期间接续操作及完整通关。测试用搜索器按等尺寸棋子合并状态，找出通关路径后，通过实际规则及触摸控制器重放；搜索器不包含在发布包中。

视觉验收使用 `npm run visual:qa`，需要本机安装 Playwright 与浏览器。可通过 `PLAYWRIGHT_MODULE` 指向已有 Playwright 模块，通过 `CHROME_EXECUTABLE` 指定浏览器。该工具使用实际小游戏模块与浏览器微信适配层，输出 320×568、375×667、390×844 三种尺寸的截图与本地预览到 `tmp/qa/`，检查真实 Canvas 绘制、动画和进度恢复。

**验证边界：**浏览器适配层与 Node 测试不能替代微信基础库、开发者工具上传包及真机触摸验收。

## 美术

当前主方案由 Canvas 本地绘制，无需网络：棋子使用固定随棋的不规则木纹、旧漆、倒角、凹槽与渐变细金线，保留古朴刻字。曹操与卒保留原配色；关羽用青玉、张飞用靛蓝、马超用古金、赵云用青灰、黄忠用紫檀色。六位角色的插画提示词见 [art-source/portraits.prompt.txt](art-source/portraits.prompt.txt)。API 已生成评审图集，作为备用方案暂未接入运行时。

棋子大字采用 [Ma Shan Zheng（马善政毛笔字）](https://github.com/googlefonts/mashanzheng)，按 SIL OFL 1.1 使用，许可随包保存在 `assets/lettering/OFL.txt`。仅提取“曹关张马赵黄卒”七个字的矢量轮廓（约 50 KB），通过 Canvas 路径绘制，避免设备系统字体差异与网络字体加载。小字保持原有风格。原始字体来自 Google Fonts，保存在不参与打包的 `art-source/lettering/`；Windows 下可运行 `./tools/build-piece-lettering.ps1` 重新生成轮廓。

已生成两份仅供评审的本地预览：

- [六格武将图集](art-source/portraits-atlas-v1.png)
- [按棋子比例放入棋盘的预览](art-source/portraits-piece-preview-v1.png)

两份图片暂未接入游戏；确认画风后，再做裁切图集、加载失败回退和微信开发者工具真机验收。
